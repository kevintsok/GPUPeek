--- Warp Efficiency Analysis ---
Compute-bound kernels benefit less from high occupancy
Memory-bound kernels need high occupancy to hide latency
Latency hiding works best with balanced compute/memory

--- Key Findings ---
1. Compute-bound: high arithmetic intensity, less sensitive to occupancy
2. Memory-bound: low arithmetic intensity, needs high occupancy for latency hiding
3. Threadgroup size affects occupancy and performance
4. Optimal occupancy depends on kernel characteristics
5. Apple M2: 8 EUs, warp size 32, max threads per EU ~1024

--- Apple M2 Architecture ---
- GPU Family: Apple 7
- EUs (Execution Units): 8
- SIMD Width: 32 threads (warp equivalent)
- Max Threads per EU: ~1024
- Threadgroup Memory: 32 KB

--- Occupancy Calculation ---
Occupancy = (Threads per Threadgroup / Max Threads per EU) * (Threadgroups / Max Threadgroups)

For Apple M2:
- Max threads per EU: 1024
- Max threadgroups per EU: Limited by register pressure

--- Optimization Strategies ---
1. For memory-bound kernels: Higher occupancy helps hide latency
2. For compute-bound kernels: Occupancy less critical
3. Use 256-512 threads as default (good balance)
4. Shared memory size affects max occupancy
5. Profile to find optimal threadgroup size

--- Trade-off Analysis ---
More threads per threadgroup:
- ✅ Higher occupancy
- ✅ Better latency hiding
- ❌ Less shared memory per thread
- ❌ More register pressure

Fewer threads per threadgroup:
- ✅ More shared memory per thread
- ✅ Less register pressure
- ❌ Lower occupancy
- ❌ Less latency hiding

--- When Occupancy Matters ---
✅ Matters (memory-bound):
- Sequential memory access
- Global memory reads/writes
- Atomic operations

❌ Less matters (compute-bound):
- FMA chains
- Register-only computation
- SIMD operations
