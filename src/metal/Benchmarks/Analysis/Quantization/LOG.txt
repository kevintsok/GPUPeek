--- Key Findings ---
1. Int8 provides 2-4x speedup vs FP16 for quantized ML inference
2. Int4 provides 4x storage reduction but may need specialized hardware
3. BFloat16 provides better dynamic range than FP16 for ML training
4. Quantization introduces accuracy vs performance tradeoff
5. Apple ANE handles low-precision natively for best efficiency

--- Quantization Types ---
| Type | Storage | Speedup | Accuracy Loss | Notes |
|------|---------|---------|---------------|-------|
| FP16 | 16-bit | 2x | <0.1% | Good baseline |
| Int8 | 8-bit | 2-4x | 1-5% | Most common |
| Int4 | 4-bit | 4-8x | 5-15% | Aggressive |
| Dynamic | Adaptive | 2-3x | 1-3% | Per-layer |

--- Quantization Process ---
1. Choose precision (Int8, Int4)
2. Determine scale factors
3. Convert weights to low precision
4. Quantize activations at runtime
5. Dequantize outputs as needed

--- Quantization Error Analysis ---
For Int8 quantization:
- Scale: (max - min) / 255
- Zero point: -min / scale
- Error: ±0.5 * scale

--- Apple Silicon Quantization Support ---
1. ANE: Native Int8/Int4 support
2. GPU (Metal): FP16 native, Int8 via emulation
3. CPU: Neon SIMD for Int8

--- Performance Comparison ---
FP16 -> Int8: 2x memory bandwidth savings
FP16 -> Int4: 4x memory bandwidth savings
Int8 -> Int4: Additional 2x savings

--- Accuracy Impact by Model Type ---
| Model | FP32 Acc | Int8 Acc | Drop |
|-------|----------|----------|------|
| ResNet50 | 76.1% | 75.5% | 0.6% |
| BERT | 92.0% | 91.2% | 0.8% |
| YOLOv3 | 55.3% | 54.1% | 1.2% |

--- When to Use Quantization ---
Use quantization when:
- Model size is too large for device
- Inference speed is critical
- Accuracy loss is acceptable (1-5%)
- Batch processing multiple inputs

Don't use quantization when:
- Highest accuracy required
- Model is already small
- Dynamic range is critical
