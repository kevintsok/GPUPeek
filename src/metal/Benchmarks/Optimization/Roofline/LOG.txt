=== Roofline Model Analysis (Compute Bound vs Memory Bound) ===

--- Roofline Parameters for Apple M2 ---
Peak Compute: ~12 GFLOPS
Peak Bandwidth: ~2 GB/s (effective, unified memory)
Crossover Point: ~6 FLOP/byte

--- Operations Classified by Arithmetic Intensity ---
Operation               | Arith Intensity | Theoretical Bound | Apple M2实测
-----------------------|-----------------|------------------|-------------
Coalesced Read         | 0 FLOP/B       | MEMORY           | 1.5 GB/s
Non-Coalesced Read     | 0 FLOP/B       | MEMORY           | 0.15 GB/s
Atomic Fetch-Add       | 0.25 FLOP/B    | MEMORY           | 0.04 GOPS
GEMM 256x256           | 42 FLOP/B      | COMPUTE          | 4.3 GFLOPS
GEMM 512x512           | 85 FLOP/B      | COMPUTE          | 13.7 GFLOPS
GEMM 1024x1024         | 171 FLOP/B     | COMPUTE          | 21.9 GFLOPS
Ray-Sphere Intersect   | ~5 FLOP/B      | BOTH             | 13.6 GOPS
N-Body (1M particles)  | 5 FLOP/B       | BOTH             | 0.74 GOPS
Histogram              | ~0.1 FLOP/B    | MEMORY           | 0.12 GOPS
Jacobi Iteration       | ~0.001 FLOP/B  | MEMORY           | 0.54 GOPS

--- Key Insights ---
1. Apple M2 is predominantly MEMORY BOUND due to unified memory
2. Unified memory shares bandwidth between CPU and GPU
3. Effective bandwidth ~2 GB/s vs theoretical 100 GB/s
4. GEMM achieves higher than theoretical compute (21.9 GFLOPS > 12 GFLOPS)
   - This suggests measurement methodology or roofline needs refinement
5. Memory-bound ops: Jacobi, Histogram, Atomic operations
6. Compute-bound ops: GEMM (with good data locality)

--- Optimization Priority ---
MEMORY BOUND (High Priority):
- Increase data locality
- Use FP16 instead of FP32
- Vectorize memory access (float4)
- Minimize memory traffic (kernel fusion)

COMPUTE BOUND (Medium Priority):
- Increase thread parallelism
- Use efficient SIMD operations
- Optimize instruction mix (FMA)
