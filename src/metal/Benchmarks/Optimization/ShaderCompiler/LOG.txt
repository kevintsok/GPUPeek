--- Key Findings ---
1. Library compilation takes ~1.1ms (one-time cost)
2. Pipeline state creation takes ~1.1ms per kernel
3. Encode overhead is ~42μs per dispatch
4. Kernel execution dominates (99%+ of time)
5. For large workloads, compilation is negligible

--- Compilation Breakdown ---
| Phase | Time | Notes |
|-------|------|-------|
| makeLibrary | ~1.1 ms | JIT compilation |
| makeFunction | ~0.1 ms | Symbol lookup |
| makeComputePipelineState | ~1.1 ms | HW pipeline setup |

--- Kernel Launch Anatomy ---
1. Encode (41.9 μs): Set pipeline, buffers, dispatch
2. Commit (<1 μs): Submit to GPU
3. Execute (6347 μs): GPU work
4. Complete: CPU notified

--- Optimization Strategies ---
1. Pre-compile shaders at startup
   - Avoid runtime compilation
   - Cache compiled libraries

2. Cache pipeline states
   - Create once, reuse many
   - Store in dictionary

3. Batch dispatches
   - Multiple kernels per command buffer
   - Reduces per-kernel overhead

4. Async compilation
   - Compile next frame while current runs
   - Use background queue

--- When Compilation Matters ---
| Scenario | Impact |
|----------|--------|
| Long-running app | Negligible (amortized) |
| Short batch jobs | Significant overhead |
| Real-time rendering | Startup cost only |
| Dynamic shader gen | Major bottleneck |

--- Measured Overhead Percentages ---
For typical kernel (6.3ms execution):
- Encode: 0.66%
- Actual work: 99.34%
- Compilation (1-time): ~0.01% per invocation (after amortization)

--- Practical Recommendations ---
1. Pre-compile all shaders at startup
2. Create pipeline states once
3. Batch kernel dispatches
4. Consider async compilation for dynamic shaders
5. Profile to find real bottlenecks
